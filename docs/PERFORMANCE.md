# 性能与可靠性改动记录

对比对象：`rust-port@88cde64`（迁移版原始 Rust 代码）与本分支 `rust`。两者功能等价：259 个单元/契约测试、39 项整机冒烟、10 项上游同步冒烟全部通过；7 个用量/定价接口在同一份 30,000 行用量日志上的输出逐字段相同。

## 测量方法

`bench/` 是独立的压测工具（不进入网关工作区和 `Cargo.lock`）。它在本机回环上启动一个 keep-alive 的假 SSE 上游，写入虚构账号，用 `--test-upstream` 启动网关，再用若干 keep-alive 客户端压 `/v1/chat/completions`。不访问任何真实上游。

```sh
cargo build --release -p wb2api
cargo run --release --manifest-path bench/Cargo.toml -- \
    --gateway target/release/wb2api --accounts 20 --conc 32 --secs 8
# 可选：--nonstream、--frames N、--usage-rows N --poll-usage-ms 1000（模拟看板轮询）
```

结束时压测工具会核对 `usage.jsonl`：每个成功请求恰好一行。

## 结果

Windows x86-64，Rust 1.98，release 构建，同一台机器、同一假上游（每个回复 40 个内容帧）。数字是单机回环压测，只用于新旧对比，不代表真实上游下的吞吐；真实场景的延迟主要由上游决定。

| 场景 | 旧 | 新 |
|---|---|---|
| 单连接流式，p50 延迟 | 6.8 ms | 0.66 ms |
| 单连接流式，吞吐 | 144 req/s | 1,446 req/s |
| 32 并发流式，吞吐 | 412 req/s | 6,450 req/s |
| 32 并发流式，p99 延迟 | 116 ms | 8.0 ms |
| 32 并发非流式，吞吐 | 416 req/s | 6,771 req/s |
| 32 并发流式，8 秒内新建上游连接 | 1,501 | 48 |
| 20 万行用量日志 + 看板每秒轮询 `/usage`：chat 吞吐 | 153 req/s | 6,586 req/s |
| 同上：chat p99 延迟 | 1,634 ms | 7.9 ms |
| 同上：`/usage` 轮询 p50 | 1,299 ms | 1.4 ms（5 秒内命中缓存） |
| 看板 HTML 传输大小（支持 gzip 的浏览器） | 1,007,540 B | 298,540 B |

单个 `/usage/*` 接口冷查询（缓存未命中）的耗时与旧版持平：瓶颈是逐行解析整份 JSONL，这次没有改动其存储格式。

## 改动内容

### 每个 chat 请求的固定开销

旧版每个请求都会：

- 重新读取并解析 `settings.json`（`snapshot()`、`keys()`、`proxy_slots()` 各一次，单个请求内累计 10 次左右）；
- 对每个账号调用一次 `catalog.list()`，为整个模型目录构造公开条目，只为得到免费/付费模型集合；
- 两次从磁盘加载定价（内置快照 JSON 解析 + 扫描 `pricing-policies.jsonl`、`pricing-timeline.jsonl`）；
- 每日用量护栏读取文件头尾签名；
- 读取多处 `WB_*` 环境变量；
- 为审计记录克隆整份规范化请求体（包含全部对话历史）。

现在：

- `wbsettings` 缓存解析后的配置、API Key 和代理槽，每次调用只做一次 `stat`，文件大小、修改时间或 inode 变化时才重新读取。面板写入后立即更新缓存；外部手工编辑也会被识别。
- 免费/付费模型集合按模型目录的修订号缓存，目录刷新时重建。
- 定价按源文件的大小和修改时间缓存；`record_policies` 写入后直接失效。
- 每日用量统计在日志未变化时直接返回共享结果；刚修改不足 2 秒的文件仍走完整内容校验，避免同一时间片内的同尺寸改写被漏判。
- 环境变量在启动时读取一次。这些开关本来就要求重启生效。
- 审计记录只保存消息摘要、条数和推理强度。

### 流式转发

- 旧版对每一行 SSE 解析两次 JSON（审计一次、协议适配器一次）。现在审计层把解析结果直接交给适配器。
- 旧版每个下游帧单独写入通道。现在一次上游读取产生的所有帧合并成一个块发送。
- 流式 chat 不再在后台构造用不到的非流式聚合结果。
- `pyjson` 字符串转义改为整段复制无需转义的部分。

### 上游连接池

- 每个凭据最多保留 16 个空闲连接（旧版 2 个）。同一账号上的并发请求以前几乎每次都要重新 TCP 连接并 TLS 握手。
- 空闲 TTL 从 90 秒降到 55 秒，低于常见服务端/负载均衡 60–75 秒的 keep-alive 超时，减少复用到已被对端关闭的连接。
- 读取直接写入连接缓冲区，不再经过栈上 16 KiB 临时数组复制。

### HTTP 服务端

- 修复可靠性问题：`accept()` 出错时旧版用 `?` 直接结束整个服务循环，文件描述符耗尽（EMFILE）一次就会让网关停止接受连接。现在单连接错误直接忽略，资源类错误短暂退避并限频记录日志。`set_nodelay` 失败不再丢弃该连接。
- 错误响应不再一律附带 `Connection: close`。只有请求体可能未读完的 408/413 仍会关闭连接；401/429/503 等常见错误之后客户端可以继续复用连接。
- 看板 HTML（约 1 MB）按界面语言渲染、计算 ETag、gzip 压缩各一次，之后直接复用。
- 面板用量接口（`/usage`、`/usage/recent`、`/usage/perf`、`/usage/timeseries`、`/usage/analytics`、`/usage/by-account`、`/pricing`）增加 5 秒响应缓存并带 ETag，对应 Python 基线的 `_STATS_TTL`。看板每 5 秒并发轮询其中三个，旧版每轮都会全量扫描用量日志三次，并占用写入锁，阻塞同一时刻的 chat 记账。定价文件、账号、API Key 变化或日志被替换/截短时缓存键随之改变；新增请求最多延迟 5 秒显示。
- 用量查询不再持有追加写锁。追加是单次 `O_APPEND` 写入，读取方本来就忽略未完成的末行。
- `/v1/models` 在开启"仅显示可用模型"时，旧版对每个模型、每个账号都构造一次完整的 `public_metadata()`；现在每个账号读取一次所需字段。

### 日志

- 内存日志改为带类型的环形缓冲，ID 单调递增（清空后也不回退）。`/logs` 增量查询用二分定位，只序列化返回的行。
- stderr 写线程把队列中已有的行合并成一次写入和一次 flush。
- 用量行的磁盘追加移到阻塞线程池，不再占用异步工作线程；关闭时最多等待 5 秒让排队的行写完。

## 未改动

- 用量日志仍是 JSONL，冷查询仍需全量扫描。改为增量聚合或 SQLite 是存储格式变更，需要单独决定。
- 未在 Linux 上实测性能；CI 在 amd64/arm64 原生 runner 上跑功能测试，不跑压测。
- 未使用真实上游账号验证。
